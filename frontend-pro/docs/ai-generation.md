# 让 AI 生成 Agent

不要只告诉 AI“写一个 Agent”。请把任务定义和平台交付契约一起提供。

## 1. 先准备任务说明

填写目标用户、任务、业务边界、输出格式、需要的 Skill/MCP/知识库，以及有风险的操作。信息未知时明确写“未知，需保守处理”。

## 2. 可复制提示词

```text
请严格按照《Agent 开发、上传与运行规范》生成一个可上传的完整 Agent 工程。

任务说明：
【填写目标用户、任务、边界、输出格式、Skill/MCP/知识库需求、风险动作】

要求：
1. 先复述职责、假设和待确认项，不虚构业务规则、平台 API、工具名或知识。
2. 交付完整目录，至少有入口、策略/提示词、固定依赖、README 和测试。
3. 入口接受 input、messages、secrets、memory、capabilities，并支持异步流式。
4. 实现初始化、理解、状态恢复、规划、执行、输出、成功后记忆和 finally 清理。
5. 步骤、超时、幂等重试和成本有明确上限，高风险动作需要确认。
6. 能力只通过 capabilities 消费；输出平台配置清单，但不编造 asset_id。
7. 密钥只声明名称，不生成真实值、.env 或泄密日志。
8. 测试覆盖正常、多轮、无知识、工具失败、超时/取消、并发和流式。
9. 没有真实平台 SDK 时使用 Protocol/adapter 和测试替身，不假造 SDK 方法。
10. 最后逐项按规范自检。

交付顺序：假设与待确认项 → 文件树 → 全部文件 → 平台配置清单
→ 测试命令与结果 → 上传参数 → 自检结果。
```

## 3. 拒收条件

### 工程不完整

- 只有单文件或代码片段；
- 只有一次 LLM 调用；
- 没有 README、固定依赖或测试；
- 测试只验证返回值不为空。

### 平台不合规

- 内联密钥、知识正文或完整 MCP 配置；
- 用模块全局变量保存对话历史；
- 使用不存在的 SDK/API 并声称可直接运行；
- 没有超时、步骤、重试或成本边界。

### 业务不可信

- 自行编造政策、工具、字段或成功标准；
- 用假数据掩盖知识无结果或工具失败；
- 对副作用操作不做权限、参数或确认检查。

## 4. AI 自检输出

要求 AI 对每条规范给出“通过 / 不适用 / 待确认”，并附对应文件位置。仅声称“全部完成”不能作为验收证据。

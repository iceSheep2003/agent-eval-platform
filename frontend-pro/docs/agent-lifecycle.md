# 运行与发布生命周期

Agent 有两个不同的生命周期：一次调用如何完成，以及一个版本如何进入生产。

## 1. 单次运行生命周期

### 初始化

读取本次注入的 secrets、memory 和 capabilities，创建调用级客户端。模块导入阶段不得执行真实业务请求。

### 理解与恢复

结合 `input` 和 `messages` 理解任务，仅从当前 memory 分区恢复必要状态。

### 规划与执行

选择适用 Skill，决定是否检索知识库或调用 MCP。限制最大步骤、总超时、成本和重试次数。

### 生成与持久化

返回文本或结构化输出。只有成功完成后才写必要记忆；模型、检索、工具和错误应进入 Trace。

### 清理

在成功、失败、超时或取消时关闭连接和临时资源。不要吞掉取消和超时异常。

## 2. 版本发布生命周期

```text
开发与本地测试
  → 上传 / 创建不可变版本
  → 静态校验 + 入口验收
  → TEST 离线评测
  → LIVESH 影子验证
  → LIVE 正式流量
  → 持续监控 / 回流 / 回退
```

### TEST

用固定版本数据集验证任务质量、安全、稳定性、延迟和成本，不接生产用户流量。

### LIVESH

复制部分真实流量给候选版本，结果不返回用户。用于发现离线数据集没有覆盖的真实分布问题。

### LIVE

正式返回结果给用户，持续记录指标和 Trace。出现质量或稳定性问题时移动通道指针回退到历史稳定版本。

## 3. 版本与快照

版本冻结后不可变，晋级只移动通道指针。每个 Run 保存 Agent、Skill、MCP 和知识库的实际版本快照，历史评测不会随之后的配置升级而漂移。

## 4. 发布门禁用例

- 正常与多轮任务；
- 空输入、越权和高风险请求；
- 知识无结果与证据不足；
- MCP 超时、错误和非法返回；
- 模型失败、总超时和流式中断；
- 并发会话隔离；
- 步骤或成本预算耗尽。

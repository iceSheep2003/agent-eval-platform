# Demo 组件选型

## 结论

Demo 采用 React 版 Ant Design Pro 的中后台布局与 Ant Design 组件体系：

- React + Vite：应用运行时和开发服务器。
- TypeScript：约束领域对象和页面状态。
- `@ant-design/pro-components`：提供 `ProLayout` 应用壳层、侧边导航和顶栏。
- `antd`：统一承载按钮、表格、表单、弹窗、抽屉、进度和状态组件。
- `lucide-react`：图标系统，避免手写 SVG 图标。
- `recharts`：质量趋势和维度图表。
- `motion`：页面切换、Trace 事件流的轻量过渡与布局动画。
- `@tanstack/react-table`：为后续可排序、筛选、分页的运行/数据集表格预留。
- 自有 CSS：在 Ant Design Pro 骨架上保留 Eval Loom 的 Trace、运行状态和数据密度。

Art Design Pro X 的产品布局和交互节奏用作设计参考；由于它基于 Vue 3 + Element Plus，不直接引入当前 React 运行时。

## 使用边界

评测平台的核心页面是 Trace、运行状态和评测能力，而不是普通 CRUD。`ProLayout` 只承载应用框架、工作区切换和导航；业务内容仍使用平台自己的信息结构。

按钮、表格、表单、弹窗和反馈统一使用 Ant Design；评测卡片、状态徽章和 Trace 时间线保留平台自己的视觉和信息结构。

## 关于 Gallery / Galary 动效组件

没有检索到一个明确叫 `Galary` 的主流 React 包。更接近的方向是 React Bits、Magic UI 这类 animated component gallery，其中有 Animated List、Blur Fade、Animated Beam 等可复制的动效组件。这个平台不适合放 3D 图片画廊，最适合的是把 Animated List 的进入、布局和退出节奏用于 Trace 事件流。

Demo 采用 `motion` 作为运行时，将这类组件的动效模式落在两个地方：

- 页面切换：当前页面以轻微的透明度和位移完成切换。
- Trace 事件流：事件逐条进入，事件列表变化时保留布局过渡。

这样可以保留现有 Eval Loom 视觉系统，也避免把整套展示站组件硬套进管理平台。React Bits 官方仓库强调组件可复制、可定制和最小依赖，Magic UI 官方目录也提供 Animated List、Blur Fade、Animated Beam 等同类组件，可作为后续继续增强的来源。

## 后续可引入的组件

### shadcn/ui / Radix

如果下一阶段需要大量 Dialog、Dropdown、Select、Tabs、Toast、Data Table，可以采用 [shadcn/ui](https://ui.shadcn.com/docs/components) 的可复制组件模式和 Radix 行为原语。这样既能复用无障碍交互，也能继续控制视觉样式。

### OpenTelemetry

前端 Demo 当前使用本地事件数据。生产版 Trace 采集建议以 [OpenTelemetry JavaScript](https://opentelemetry.io/docs/languages/js/) 为底层协议，平台补充 `run_id`、`trial_id`、`session_id`、`agent_version`、`benchmark_version` 和 `scorer_version` 等评测字段。

### 评测执行内核

Benchmark 适配与容器执行不重复造轮子：

- 统一任务协议参考 Exgentic 的 `Task / Context / Actions`。
- 容器化任务参考 Harbor 的 `Task / Dataset / Trial / Job`。
- Benchmark Adapter 采用 Harbor 的任务目录和 parity 验证思路。
- 后续接入真实 MCP / A2A Agent 时分别实现协议 Adapter，不改 Runner 的核心循环。

## 依赖使用边界

依赖只解决通用能力，不承载平台领域规则：

```text
依赖库：图标、图表、表格交互、可观测性传输、容器运行时
平台代码：Agent、Benchmark、Dimension、Run、Trace、Score、Audit
```

这样在替换某个 UI 或执行组件时，不会影响评测领域模型。

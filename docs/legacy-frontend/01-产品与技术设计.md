# Agent 评测平台：产品与技术设计

## 1. 产品定位

这是一个面向 Agent 系统的评测管理与运行平台，重点评估“模型 + Agent Harness + 工具 + 记忆 + 环境 + 策略”组成的完整系统，而不是只评估一次模型回答。

平台需要同时解决四件事：

1. 管理被测 Agent 以及它的版本、依赖、工具、运行配置。
2. 管理评测能力、评测维度、数据集和 Benchmark Adapter。
3. 在隔离环境中启动评测任务，记录每一步 Agent 行为、工具调用、模型调用和环境变化。
4. 将原始评分、过程指标、成本指标和审计结论汇总成可比较的报告。

## 2. 不做什么

第一版不做通用 Agent 编排平台，也不试图替代 LangGraph、OpenAI Agents SDK、CrewAI 等 Agent 框架。

第一版也不直接实现所有 Benchmark。平台只提供一套稳定的接入协议和适配器机制，先接入少量可控的数据集验证闭环，再逐个增加 Benchmark。

## 3. 用户与典型流程

### 3.1 Agent 开发者

```text
注册 Agent
  → 选择 HTTP / MCP / CLI / 代码包接入方式
  → 创建版本并填写运行清单
  → 运行冒烟任务
  → 查看轨迹和失败原因
  → 对比不同版本
```

### 3.2 评测设计者

```text
创建评测能力
  → 绑定一个或多个维度
  → 选择数据集和 Benchmark Adapter
  → 设置评分器、预算、并发和安全策略
  → 发布评测模板
```

### 3.3 评测执行者

```text
选择 Agent 版本 + 评测模板
  → 创建运行实例
  → 启动任务
  → 观察运行状态和实时轨迹
  → 暂停 / 恢复 / 终止
  → 查看任务级、维度级和总体报告
```

### 5.1 控制面

控制面负责声明和管理，不直接执行不可信 Agent 代码：

- Agent 注册、版本冻结、接入凭证和状态管理。
- 评测能力、维度、数据集、模板和版本管理。
- 创建 Run、分配任务、控制暂停/恢复/终止。
- 记录状态转换、操作人和配置快照。
- 汇总结果，生成报告和比较视图。

### 5.2 执行面

执行面负责运行不可信代码和真实环境：

- 为每个 Trial 分配隔离沙箱。
- 加载指定 Agent 版本和 Benchmark 版本。
- 将统一协议转换成 Agent 原生协议。
- 记录完整轨迹和运行指标。
- 执行确定性测试与规则评分。

控制面和执行面必须通过消息或任务 API 解耦，不能让 Web 请求线程直接运行长时间 Agent 任务。

## 6. 核心业务对象

### 6.1 Agent

一个被测智能体的逻辑身份，不等于某一次运行。

关键字段：

```text
id
name
description
owner
connect_type: http | mcp | cli | package | python
status: active | paused | disabled
created_at
```

### 6.2 AgentVersion

Agent 的可复现版本。每次评测必须绑定具体版本，而不是绑定“当前代码”。

关键字段：

```text
agent_id
version
source_type
source_digest
image_digest / package_digest
runtime_manifest
model_config
tool_config
prompt_version
dependency_lock
created_by
```

### 6.3 Capability

平台预定义的评测能力，例如：

- 工具选择与参数正确性
- 多步任务完成
- 规则遵循
- 事实性与引用支撑
- 规划与恢复
- 记忆使用
- 安全边界与越权防护
- 成本、延迟和资源效率

能力是产品目录，不直接等于一个分数。

### 6.4 Dimension

能力下面可配置的具体评测维度。例如“工具使用能力”下可以包含：

```text
工具选择准确率
参数 Schema 合规率
工具调用成功率
错误恢复率
无效调用率
工具调用成本
```

每个维度需要声明：数据类型、评分方法、是否确定性、权重、阈值和失败等级。

### 6.5 Dataset

数据集是任务样本的集合，可以来自：

- 内置 Benchmark Adapter
- 用户上传的 JSONL / CSV / Parquet
- 平台生产失败样本
- 人工编写的回归集
- 从历史 Trace 筛选出的案例

### 6.6 EvaluationTemplate

评测模板将能力、维度、数据集、Agent 运行配置和评分策略组合起来，供执行者直接创建 Run。

### 6.7 Run / Trial / Session

```text
Run       一次批量评测
Trial     一个任务的一次 Agent 尝试
Session   Agent 与环境的一次连续交互会话
Trace     Session 内的完整事件树
```

一个 Run 可以包含多个 Dataset、多个 AgentVersion 和多个 Trial。

## 7. 评测维度管理

平台应采用“能力 → 维度 → 指标/评分器 → 数据集”的四级结构：

```text
工具调用能力
├── 选择正确性
│   └── ToolSelectionAccuracy
├── 参数正确性
│   └── ArgumentSchemaCompliance
├── 调用可靠性
│   └── ToolSuccessRate
└── 失败恢复
    └── RecoveryRate
```

同一个数据集可以被多个能力使用，同一个维度也可以绑定多个数据集。平台不应把数据集和能力硬编码成一对一关系。

每个评分器分两类：

### 确定性评分器

- 测试用例是否通过。
- JSON Schema 是否合规。
- 是否调用了允许的工具。
- 是否发生越权调用。
- 是否产生正确文件、补丁或数据库状态。
- 任务是否在预算内完成。

### 语义评分器

- LLM-as-Judge。
- 规则 + 模型的混合评分。
- 人工复核。
- 引用真实性和上下文一致性判断。

原则是：能确定性判断的内容不要交给 LLM Judge；LLM Judge 必须记录模型、提示词、版本、输入证据和成本。

## 8. 类 Langfuse 的运行观测

平台需要提供类似 Langfuse 的 Trace 视图，但对象应扩展到整个评测过程：

```text
Run
└── Trial
    └── Session
        ├── Agent turn
        │   ├── Model request
        │   ├── Model response
        │   ├── Tool call
        │   └── Tool result
        ├── Environment event
        ├── Scorer event
        └── Audit event
```

最小审计信息包括：

- 谁发起了 Run。
- 使用了哪个 Agent 版本。
- 使用了哪个模型和模型参数。
- 发送给模型的系统提示词和工具 Schema 版本。
- Agent 调用了哪些工具、传入了什么参数、返回了什么结果。
- 环境状态发生了什么变化。
- 何时暂停、恢复、超时或终止。
- 评分器使用了什么版本和输入证据。
- 最终产物的内容摘要和哈希。

敏感内容应支持脱敏、加密和按字段访问控制，不能把 API Key、完整用户隐私数据和内部凭证直接展示在 Trace 页面。

## 9. Agent 生命周期管理

Agent 逻辑状态和 Agent 运行状态分开管理。

```text
Agent 状态：active / paused / disabled
运行状态：created / queued / starting / running / pausing / paused
          / resuming / stopping / completed / failed / cancelled
```

暂停行为必须定义清楚：

- 对 HTTP/MCP Agent：停止发送新任务或发送 pause 控制信号。
- 对容器 Agent：冻结或暂停容器，并持久化 Session 状态。
- 对不可恢复 CLI：标记为“停止后不可恢复”，重新创建 Trial。

第一版可以先实现“停止接收新任务”和“终止当前 Trial”，不要假装所有 Agent 都能安全暂停。

## 10. 外部 Agent 接入

### 10.1 HTTP Agent

适合生产服务和远程 Agent。平台调用 Agent 的统一接口：

```text
POST /v1/eval-sessions
POST /v1/eval-sessions/{session_id}/observations
POST /v1/eval-sessions/{session_id}/actions
POST /v1/eval-sessions/{session_id}/finish
POST /v1/eval-sessions/{session_id}/cancel
```

生产环境建议采用反向连接或平台内网访问，避免直接暴露带权限的 Agent 地址。

### 10.2 MCP Agent

平台可以把 Benchmark actions 暴露为临时 MCP Server。每个 Session 使用独立工具集合、凭证和生命周期，Session 结束后立即回收。

### 10.3 CLI / Docker Agent

平台为每个 Trial 创建容器，挂载任务工作区，注入任务和凭证，通过 stdout、JSONL 或文件协议收集结果。

### 10.4 Agent 代码包

上传包必须经过：

1. 文件类型和大小校验。
2. 恶意脚本和依赖扫描。
3. 在隔离构建环境生成镜像。
4. 固化依赖锁文件和镜像 Digest。
5. 运行最小权限、只读根文件系统和网络白名单。
6. 通过健康检查和冒烟任务后，才能进入可运行状态。

代码包上传后不能直接在 API 服务进程中 import 并执行。

## 11. 第一版推荐技术栈

### Demo 阶段

- 前端：React + TypeScript + Vite。
- 后端：FastAPI。
- 数据：SQLite 或 PostgreSQL。
- 任务队列：先用进程内后台任务，随后替换 Redis + Celery/RQ/Arq。
- 运行环境：Docker。
- 轨迹：JSONL + SQLite；后续切换 PostgreSQL + 对象存储。
- 协议：HTTP JSON，兼容 OpenAI Tool Schema，预留 MCP/A2A。

### 生产阶段

- 前端静态资源：Nginx 或 CDN。
- API：FastAPI 多副本 + Gunicorn/Uvicorn。
- Worker：Kubernetes Job / Argo Workflows / 自研 Runner。
- 队列：Redis Streams、RabbitMQ 或 Kafka。
- 元数据：PostgreSQL。
- 轨迹与包：S3/MinIO/OSS。
- 可观测性：OpenTelemetry + Prometheus + Loki/ClickHouse。
- 容器隔离：Kubernetes + gVisor/Kata，必要时远程 Sandbox。

## 12. 第一版 Demo 的产品边界

必须做：

- 仪表盘：运行数、成功率、失败数、成本和延迟。
- Runs：创建、启动、停止、查看状态。
- Trace：按 Run/Trial 查看步骤、动作、观测、工具调用。
- Agent：注册、启用、暂停、版本、HTTP Agent 示例。
- 代码包：上传记录和模拟执行入口；真正执行放到后续隔离 Worker。
- Capability / Dimension：创建、启用、权重和阈值。
- Dataset：创建、导入 JSONL、绑定维度。
- Evaluation Template：选择 Agent、能力和数据集后创建运行。
- 结果：任务级、维度级和总体分数。

可以暂缓：

- 多租户计费。
- 完整 RBAC/SSO。
- Kubernetes 多集群调度。
- 浏览器和桌面 GUI 环境。
- 强一致的跨区域容灾。
- 复杂的人工标注工作流。

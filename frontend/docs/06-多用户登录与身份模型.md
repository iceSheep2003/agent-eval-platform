# 多用户登录与身份模型（Demo）

## 目标

这个 Demo 先验证多用户评测平台最小闭环：

1. 用户登录后才能进入评测工作台。
2. 后端根据用户返回可访问的工作区。
3. 前端显示当前用户、角色和工作区，并支持切换。
4. 退出登录后清理服务端 Session，重新回到登录页。

## API

- `POST /api/auth/login`：提交 `{ "identifier": "admin", "password": "admin123" }`，服务端设置 HttpOnly Session Cookie。
- `GET /api/auth/me`：读取当前登录用户和工作区。
- `GET /api/workspaces`：读取当前用户可以访问的工作区。
- `POST /api/auth/logout`：注销并清理 Session Cookie。
- `GET /api/health`：健康检查。

## 当前实现边界

这是用于快速验证产品交互的本地 Demo，不是生产身份系统：

- 用户数据放在 `server/data/users.json`，密码使用 Node `scrypt` 哈希，不保存明文密码。
- Session 暂存在 API 进程内存，服务重启后全部失效，也不支持多实例共享。
- 工作区、角色和权限暂时是静态数据，尚未接数据库和审计持久化。
- 还没有注册、找回密码、验证码、SSO、MFA、登录限流和 CSRF 防护。

## 上生产前的替换清单

1. 身份认证接入 OIDC / SAML，优先使用企业 IdP 或 Keycloak；平台只消费标准 Token 和用户声明。
2. 用户、组织、工作区、成员关系、角色权限落到 PostgreSQL，并引入迁移和唯一约束。
3. Session 使用 Redis 或无状态短期 JWT + Refresh Token；Cookie 必须设置 `Secure`、`HttpOnly`、`SameSite`。
4. 评测对象、数据集、Trace、评分结果全部带 `org_id` / `workspace_id`，服务端每个查询都做租户隔离。
5. 对登录、Agent 接入、代码包上传、运行控制和权限变更写入不可抵赖的审计日志。
6. 增加登录失败限流、账号锁定、MFA、密钥托管、CSP、CSRF 和依赖/镜像扫描。

建议把这个 Demo 的工作区切换保留为平台一级上下文：后续所有评测运行、数据集、Agent、Trace 和报告都从当前工作区派生，而不是依赖前端传来的任意 ID。
